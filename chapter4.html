BIG IDEA

Stored-Program Concept — โปรแกรมถูกเก็บเหมือนข้อมูล

หลักการสำคัญ 2 ข้อ ที่เป็นรากฐานของคอมพิวเตอร์ยุคใหม่ทุกเครื่อง

ข้อ 1 · คำสั่งก็คือตัวเลข

Instruction (คำสั่ง) ไม่ต่างจากตัวเลข 5 หรือ 100 — เพียงแต่ตัวเลขนี้ถูกตีความว่า "ให้ทำอะไร"

ข้อ 2 · เก็บใน RAM ตัวเดียวกับข้อมูล

โปรแกรมทั้งโปรแกรมเก็บในหน่วยความจำเดียวกันกับข้อมูล — ไม่ต้องแยก RAM สำหรับโปรแกรมและข้อมูล

Memory (RAM) — เก็บได้ทั้ง 2 อย่าง
0x00400000000000 01001 01010คำสั่ง
0x00400004000011 00000 00000คำสั่ง
0x00400008100011 01001 00000คำสั่ง
0x100100000000 0000 0000 0101ข้อมูล
0x100100040000 0000 0000 0110ข้อมูล
0x100100080000 0000 0000 0111ข้อมูล
เปรียบเทียบง่าย ๆ — ตู้ล็อกเกอร์ที่มีเลขกำกับ (address) บางล็อกเกอร์เก็บ "ของ" (data) บางล็อกเกอร์เก็บ "ใบสั่งงาน" (instruction) แต่ทั้งสองแบบก็แค่ "กระดาษที่มีตัวเลข" — เก็บในตู้เดียวกันได้หมด
PC (Program Counter) — ตัวนับพิเศษที่คอยจำว่า "ตอนนี้กำลังรันคำสั่งอยู่ที่ address ไหน" เหมือนนิ้วที่ชี้บรรทัดที่กำลังอ่าน

CONSEQUENCES

เมื่อโปรแกรมเป็นแค่ตัวเลข — ผลที่ตามมา

จากหลักการ Stored-Program มีผลลัพธ์สำคัญ 2 อย่างที่ต้องรู้

1 · ทุกอย่างมีที่อยู่ (Address)

ทั้งคำสั่งและข้อมูลมี address หมด และมี PC ที่ชี้ว่า "ตอนนี้อยู่ที่ไหน" — เหมือนนิ้วชี้บรรทัดในหนังสือ

2 · Backward Compatible

โปรแกรมที่คอมไพล์แล้ว (binary) ผูกติดกับชุดคำสั่งของ CPU รุ่นนั้น — CPU รุ่นใหม่ต้องรองรับคำสั่งรุ่นเก่าด้วย ไม่งั้นโปรแกรมเก่าจะรันไม่ได้

จำง่าย ๆคำสั่งคอมพิวเตอร์ไม่ใช่อะไรลึกลับ — มันคือตัวเลข 32 บิตที่ถูกแบ่งเป็นช่อง ๆ ตามกติกาที่ตกลงกันไว้ล่วงหน้า และเพราะมันเป็นแค่ตัวเลข จึงเก็บในหน่วยความจำเดียวกับข้อมูลได้

HOW INSTRUCTIONS BECOME NUMBERS

คำสั่งกลายเป็นตัวเลขได้อย่างไร?

ข้อมูลทุกอย่างในคอมพิวเตอร์จัดเป็นก้อน 32 บิต (word) — MIPS จึงเลือกให้คำสั่งมีขนาด 32 บิตเท่ากัน เพื่อความเรียบง่าย

1 Word = 32 Bits
10001010 00001000 00100000 00000000

แบ่งเป็นช่อง (Fields)

เมื่อคำสั่งมีขนาดคงที่ 32 บิต เราก็แบ่งเป็น "ช่อง" แต่ละช่องบอกข้อมูลคนละอย่าง — คล้ายแบบฟอร์มที่มีช่องกรอกชื่อ, ช่องวันเกิด, ช่องที่อยู่

3 รูปแบบ (Formats)

MIPS มีรูปแบบคำสั่ง 3 แบบ: R-Format (Register) · I-Format (Immediate) · J-Format (Jump)

FORMAT 1/3

R-Format — ใช้กับคำสั่งที่ทำงานกับ Register ล้วน ๆ

เช่น add, sub, slt, sll — แบ่ง 32 บิตเป็น 6 ช่อง: opcode + rs + rt + rd + shamt + funct = 6+5+5+5+5+6 = 32 bits

opcode6 บิต
rs5 บิต
rt5 บิต
rd5 บิต
shamt5 บิต
funct6 บิต
ช่องความหมายจำแบบประโยค
opcodeบอกกลุ่มคำสั่งคร่าว ๆ — R-format มีค่าเป็น 0 เสมอ—
rsRegister ตัวตั้งต้น (operand แรก)"เอา rs กับ rt มาบวกกัน"
rtRegister ตัวที่สอง (operand ที่สอง)
rdRegister ปลายทาง — เก็บผลลัพธ์"แล้วเก็บผลไว้ที่ rd"
shamtShift Amount — ใช้กับคำสั่ง shift (sll, srl) คำสั่งอื่นใส่ 0—
functใช้ร่วมกับ opcode ระบุคำสั่งที่แน่นอน เช่น add, sub—
ทำไม 5 บิต / 6 บิต? 5 บิตแทนเลข 0–31 ได้พอดี — MIPS มี register 32 ตัว (พอดีเป๊ะ!) ส่วน 6 บิตแทนเลข 0–63 ได้

WORKED EXAMPLE

ตัวอย่างจริง: add $8,$9,$10 → 0x012A4020

แปลว่า $8 = $9 + $10 — ไล่ทีละช่อง แล้วต่อเป็นเลขฐาน 16

ช่องค่าความหมาย
opcode0เป็น R-format
rs9operand แรก ($9)
rt10operand ที่สอง ($10)
rd8ปลายทาง ($8)
shamt0ไม่ใช่ shift
funct32คำสั่ง add
000000opcode=0
01001rs=9
01010rt=10
01000rd=8
00000shamt=0
100000funct=32
ขั้นที่ 1 ต่อทุกช่องเป็นเลขฐาน 2: 000000 01001 01010 01000 00000 100000
ขั้นที่ 2 จับกลุ่ม 4 บิต: 0000 0001 0010 1010 0100 0000 0010 0000
ขั้นที่ 3 แปลงแต่ละกลุ่ม 4 บิตเป็นเลขฐาน 16: 0 1 2 A 4 0 2 0 → 0x012A4020 — นี่คือภาษาเครื่องตัวจริงที่ CPU อ่าน!

FORMAT 2/3

I-Format — Immediate

คำสั่งอย่าง addi $t0,$t1,100 ต้องการ "เลขคงที่" (100) ไม่ใช่ register ตัวที่สาม — เลขคงที่มักใหญ่เกิน 5 บิต จึงต้องมีรูปแบบใหม่

opcode6 บิต
rs5 บิต
rt5 บิต
immediate16 บิต

opcode บอกคำสั่งได้ครบ

opcode ยังอยู่ตำแหน่งเดิม (บิตแรก) เหมือน R-format — ฮาร์ดแวร์ตรวจสอบ opcode ก่อนเสมอ ไม่ต้องรู้ล่วงหน้าว่าเป็น format ไหน แต่ I-format ไม่ต้องมี funct ช่วย

immediate 16 บิต signed

ค่าประมาณ -32,768 ถึง 32,767 (ติดลบได้) — เก็บเลขคงที่ / offset / branch displacement

จำไว้I-Format = addi, lw, sw, beq, bne — คำสั่งที่มี Immediate/Offset/Branch displacement

WORKED EXAMPLE

ตัวอย่างจริง: addi $21,$22,-50

แปลว่า $21 = $22 + (-50) — สังเกตว่า addi ใช้ immediate จึงเป็น I-Format

ช่องค่าหมายเหตุ
opcode8addi — บอกคำสั่งได้ครบในตัวเอง
rs22register ต้นทาง ($22)
rt21register ปลายทาง ($21) — ใน I-format rt รับผลลัพธ์
immediate-50เลขคงที่ 16 บิต (ในรูป two's complement = 0xFFCE)
001000opcode=8
10110rs=22
10101rt=21
1111111111001110imm = -50
ลำดับการอ่าน ต่างจาก R-format: ใน addi ช่องที่สอง (rs) คือค่าที่เอามาบวก ช่องที่สาม (rt) คือที่เก็บผลลัพธ์
ตัวอย่างอีกอัน lw $t0,4($s1) — rs = $s1 (base), immediate = 4 (offset) ส่วน rt = $t0 ปลายทางที่โหลดมาใส่

FORMAT 3/3

J-Format — Jump

การ "jump" ต้องระบุตำแหน่งปลายทางแบบเต็ม ๆ ซึ่งต้องการบิตเยอะ — จึงยุบทุกช่องที่เหลือเป็นช่อง target address ใหญ่ช่องเดียว

opcode6 บิต
target address26 บิต

j label

Jump — กระโดดไปที่ตำแหน่งของ label ทันที ไม่สนใจเงื่อนไข

jal function

Jump And Link — เก็บ address กลับไว้ที่ $ra ก่อน แล้วกระโดดไปฟังก์ชัน (ใช้เรียก procedure)

จำ 3 ตัวนี้ให้ขึ้นใจ R = Register · I = Immediate · J = Jump — opcode = 0 คือ R-format, opcode 2/3 คือ J-format, นอกนั้นคือ I-format

ADDRESSING · BRANCH

Branch ใช้ที่อยู่แบบสัมพัทธ์ (PC-Relative)

beq/bne ใช้ I-format มี immediate แค่ 16 บิต — ไม่พอเก็บ address เต็ม 32 บิต แล้วจะกระโดดยังไง? ตอบ: เก็บเป็น "จำนวนคำสั่งที่ต้องข้าม" แทน

ถ้าไม่ branch: PC ใหม่ = PC + 4
ถ้า branch: PC ใหม่ = (PC + 4) + (immediate × 4)

ทำไมต้องคูณ 4?

คำสั่งแต่ละตัวมีขนาด 4 bytes เท่ากันเป๊ะ → immediate เก็บเป็น "จำนวนคำสั่ง" แทน "จำนวน bytes" → กระโดดได้ไกลขึ้น 4 เท่าโดยใช้บิตเท่าเดิม

ตัวอย่าง (จับมือคิด)

0x00400020 beq $t0,$t1,L # L อยู่ถัดไป 2 คำสั่ง → imm = 2 0x00400024 add $t0,$t1,$t2 0x00400028 sub $t3,$t4,$t5 0x0040002c L: sw $t0,0($s1)
1. beq อยู่ที่ 0x00400020 — คำสั่งเองกิน 4 bytes → ตัวต่อไปคือ PC + 4 = 0x00400024
2. imm = 2 หมายถึง "ข้ามไปอีก 2 คำสั่ง" → ขยับเพิ่ม 2 × 4 = 8 (เพราะแต่ละคำสั่ง = 4 bytes)
3. บวกเลข hex: 0x00400024 + 8 — ดูหลักสุดท้าย 24 + 8 = 2c (เพราะ 0x24 = 36, 36+8 = 44 = 0x2c)
4. ได้ 0x0040002c = ตำแหน่ง L พอดี ✓ (PC ใหม่ = (PC+4) + imm×4)

ADDRESSING · JUMP

Jump ใช้ที่อยู่แบบสัมบูรณ์ (Absolute)

J-format มี target แค่ 26 บิต แต่ address จริงมี 32 บิต — ขาดไป 6 บิต แก้ด้วย 2 เทคนิค

เทคนิค 1 · ตัด 2 บิตท้าย

คำสั่งอยู่ที่ address ที่หาร 4 ลงตัวเสมอ (word-aligned) → 2 บิตท้ายเป็น 00 เสมอ ไม่ต้องเก็บ

เทคนิค 2 · ยืม PC บน 4 บิต

4 บิตบนสุด หยิบจาก PC ปัจจุบันเลย (ไม่ได้เก็บในคำสั่ง)

PC ใหม่ = { 4 บิตบนของ PC เดิม , target 26 บิต , 00 } = ครบ 32 บิต
ตัวอย่าง: j 0x00400044 (j อยู่ที่ 0x00400030)
ขั้น 1 เขียน target เป็นเลขฐาน 2 (32 บิต): 0x00400044 = 0000 0000 0100 0000 0000 0000 0100 0100
ขั้น 2 2 บิตท้ายเป็น 00 เสมอ (word-aligned) → ตัดทิ้งได้ เหลือ 0x00100011 (26 บิต) เก็บลงในคำสั่ง
ขั้น 3 PC ปัจจุบัน 0x00400030 → 4 บิตบนสุด = 0 (เอามาต่อหน้า ไม่ต้องเก็บ)
ขั้น 4 ประกอบกลับ: 0 + 0x00100011 + 00 = 0x00400044 ✓
จำง่าย ๆ "หาร 4" = ตัด 2 บิตท้ายออก เพราะ address ลงท้าย 00 เสมอ — พอประกอบกลับก็แค่เติม 00 ต่อท้าย

DISASSEMBLY

ถอดรหัสย้อนกลับ: เลข 0/1 → Assembly

ตรงข้ามกับ Assembly — เรามีเลข 32 บิต แล้วต้องรู้ว่ามันคือคำสั่งอะไร

ขั้น 1 ดู opcode (6 บิตแรก) ก่อนเสมอ — opcode = 0 คือ R-format · opcode 2/3 คือ J-format · นอกนั้นคือ I-format
ขั้น 2 เมื่อรู้ format แล้ว แบ่งบิตที่เหลือตามช่องของ format นั้น
ขั้น 3 แปลแต่ละช่องเป็นชื่อ register / ตัวเลข แล้วเขียนเป็น Assembly (ขั้นสูง: แปลงเป็นโค้ด C ที่มีความหมาย เช่น while loop)
ตัวอย่าง: 0x012A4020
ขั้นคำนวณผล
ดู opcode000000R-format
แบ่งช่อง000000 01001 01010 01000 00000 100000rs=9 · rt=10 · rd=8 · funct=32
แปล register$8=$t0 · $9=$t1 · $10=$t2add $t0,$t1,$t2

funct = 32 = add → คำสั่งนี้คือ add $t0,$t1,$t2 (หรือ add $8,$9,$10)

วิธีจำชื่อ register ตัวเลข (ข้อสอบชอบถาม)เลข 8–15 = $t0–$t7 · เลข 16–23 = $s0–$s7 — เช่น rs = 9 → 9 นับต่อจาก 8 ($t0) ได้ $t1, rd = 8 → $t0

PSEUDOINSTRUCTIONS

คำสั่งลวงตา (Pseudoinstruction) — MAL vs TAL

move, li, la ไม่มีอยู่จริงในฮาร์ดแวร์ — Assembler แปลงให้เป็นคำสั่งจริง 1 ตัวหรือมากกว่านั้นโดยอัตโนมัติ

move $t0,$t1

→ แปลงเป็น add $t0,$zero,$t1 (บวก 0 = คงค่า)

li ค่าใหญ่เกิน 16 บิต

→ แปลงเป็น 2 คำสั่ง: lui (ใส่ครึ่งบน) + ori (ใส่ครึ่งล่าง)

ชื่อคืออะไรตัวอย่าง
MALMIPS Assembly Language — ภาษาที่โปรแกรมเมอร์เขียนได้ รวมคำสั่งลวงตาmove $t0,$t1 · li $s0,0x12345678
TALTrue Assembly Language — ชุดคำสั่งที่แปลงเป็นเลขฐาน 2 ได้โดยตรง (ไม่มีคำสั่งลวงตา)add $t0,$zero,$t1 · lui + ori
ห้ามใช้ $at เอง! เวลา Assembler แปลงคำสั่งลวงตา มันใช้ register ชั่วคราวชื่อ $at (assembler temporary) — ถ้าโปรแกรมเมอร์ใช้ $at เอง อาจถูกเขียนทับโดยไม่รู้ตัว
โปรแกรมต้องถูกแปลง: MAL → TAL → เลขฐาน 2 ก่อนถึงจะรันบนฮาร์ดแวร์ได้จริง

คำถามยอดฮิต — ลองตอบในใจก่อนดูคำตอบ

MIPS Instruction มีขนาดเท่าไร?

32 bits = 4 bytes คงที่ทุกคำสั่ง

R-Format มีช่องอะไรบ้าง?

opcode, rs, rt, rd, shamt, funct

I-Format มีช่องอะไรบ้าง?

opcode, rs, rt, immediate

J-Format มีช่องอะไรบ้าง?

opcode, target address

Immediate คืออะไร?

ค่าตัวเลขที่อยู่ใน Instruction โดยตรง เช่น 10 ใน addi $t0,$t1,10

branch คำนวณ PC ยังไง?

PC ใหม่ = (PC+4) + immediate×4 · jump = {PC บน 4, target 26, 00}

move $t0,$t1 แปลงเป็น?

add $t0,$zero,$t1 — pseudoinstruction (MAL) → TAL

opcode = 0 คือ?

R-format — ต้องดู funct ร่วมด้วยเพื่อรู้คำสั่งที่แน่นอน (add = 32)

EXAM PROGRAM · fib.asm

โปรแกรมข้อสอบ: Fibonacci (fib.asm)

โปรแกรมเรียกซ้ำ (recursion) ที่ออกข้อสอบท้ายบท 20 ข้อ — main เรียก fib(7) แล้วเก็บผลลัพธ์ไว้ที่ $s5

.text 0x00400000 main: addi $a0,$zero,7 0x00400004 jal fib 0x00400008 add $s5,$v0,$zero 0x0040000c j exit 0x00400010 fib: addi $sp,$sp,-12 # จอง stack 12 bytes (3 ช่อง) 0x00400014 sw $ra,8($sp) # เก็บ address กลับ 0x00400018 sw $s0,4($sp) # เก็บ $s0 0x0040001c addi $v0,$zero,1 # base case: คืนค่า 1 0x00400020 beq $a0,$zero,fin # a0==0 → จบ 0x00400024 addi $t0,$zero,1 0x00400028 beq $a0,$t0,fin # a0==1 → จบ 0x0040002c addi $a0,$a0,-1 # a0-1 0x00400030 sw $a0,0($sp) # เก็บ a0-1 0x00400034 jal fib # fib(a0-1) 0x00400038 lw $a0,0($sp) # คืนค่า a0 0x0040003c addi $a0,$a0,-1 # a0-2 0x00400040 add $s0,$v0,$zero # s0 = fib(a0-1) 0x00400044 jal fib # fib(a0-2) 0x00400048 add $v0,$v0,$s0 # v0 = fib(a0-1)+fib(a0-2) 0x0040004c fin: lw $s0,4($sp) 0x00400050 lw $ra,8($sp) 0x00400054 addi $sp,$sp,12 0x00400058 jr $ra 0x0040005c exit: add $zero,$zero,$zero

โปรแกรมนี้คืออะไร?

fib(n) = fib(n-1) + fib(n-2) โดย fib(0) = fib(1) = 1 → ลำดับ 1, 1, 2, 3, 5, 8, 13, 21 → fib(7) = 21
⚠️ ถ้าเป็น Fibonacci มาตรฐาน (fib(0) = 0, fib(1) = 1) → ลำดับ 0, 1, 1, 2, 3, 5, 8, 13 → fib(7) = 13

ใช้ address อะไร?

text เริ่ม 0x00400000 (แต่ละคำสั่งห่าง 4 bytes) · $sp เริ่มต้น 0x7fffeffc · แต่ละครั้งเข้า fib ลด sp ลง 12

TRACE · STACK & RECURSION

fib.asm — ไล่ทีละคำสั่ง กับ Stack

กดปุ่มเพื่อดู stack เติบโตทีละเฟรม (การลงลึกครั้งแรกของ fib(7))

กดปุ่มเพื่อเริ่มไล่ stack 🔽
กฎของ jal jal เก็บ $ra = address ของคำสั่งถัดไป แล้วกระโดด
กฎของ stack เข้า fib: addi $sp,$sp,-12 → เก็บ $ra ที่ 8($sp), $s0 ที่ 4($sp), $a0 ที่ 0($sp)
ความลึกสูงสุด 7 เฟรม (fib(7)→fib(1)) = 7×12 = 84 bytes → $sp ต่ำสุด 0x7fffefa8
$ra มีค่าแค่ 3 แบบ 0x00400008 (จาก main) · 0x00400038 (jal ซ้าย) · 0x00400048 (jal ขวา)
เฟรม (depth)ฟังก์ชัน$sp หลัง addi -12$ra ที่เก็บ (8($sp))$a0 ที่เก็บ (0($sp))

นับจำนวนครั้งที่ fib ถูกเรียก (ข้อ 11)

1. สูตร: C(0) = C(1) = 1, C(n) = 1 + C(n-1) + C(n-2)
2. C(2)=3, C(3)=5, C(4)=9, C(5)=15, C(6)=25, C(7)=41 ครั้ง
3. แต่ละครั้งจอง 12 bytes → 41 × 12 = 492 bytes (รวมทั้งโปรแกรม)
4. สูงสุดพร้อมกัน = 7 เฟรม × 12 = 84 bytes

นับจำนวนครั้งที่เก็บค่า $ra (ข้อ 18–19)

1. jal ใน main → $ra = 0x00400008 — เกิด 1 ครั้ง (ข้อ 18)
2. fib ทุกครั้งที่ n ≥ 2 จะรัน jal ซ้าย (0x00400034) และ jal ขวา (0x00400044) อย่างละ 1 ครั้ง
3. นับ fib(n≥2): fib(7)=1, fib(6)=1, fib(5)=2, fib(4)=3, fib(3)=5, fib(2)=8 → รวม 20
4. → $ra = 0x00400048 (jal ขวา) ถูกเก็บ 20 ครั้ง (ข้อ 19)

CHAPTER SUMMARY

สรุปบทเรียน

เก็บทุกประเด็นสำคัญของบทนี้ไว้ในหน้าเดียว

Stored-Program

คำสั่งก็คือตัวเลข 32 บิต — เก็บใน Memory เดียวกับข้อมูล

PC

Program Counter — ชี้ address ของคำสั่งที่กำลังจะรัน

32 Bits

ทุกคำสั่ง MIPS = 32 bits = 4 bytes คงที่

R-Format

opcode|rs|rt|rd|shamt|funct — add, sub, slt, sll

I-Format

opcode|rs|rt|immediate — addi, lw, sw, beq, bne

J-Format

opcode|target(26) — j, jal

Branch vs Jump

branch = (PC+4)+imm×4 (สัมพัทธ์) · jump = {PCบน4, target, 00} (สัมบูรณ์)

MAL → TAL

Assembler แปลง pseudoinstruction (move, li) → คำสั่งจริง ใช้ $at

จำแบบนี้R = Register · I = Immediate · J = Jump · opcode=0 คือ R · add $8,$9,$10 = 0x012A4020 · fib เรียกตัวเองโดยใช้ stack เก็บ $ra ที่ 8($sp)
