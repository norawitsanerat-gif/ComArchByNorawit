MEMORY · LW ⭐⭐⭐

lw — Load Word

lw = Load Word — เอาข้อมูลจาก Memory → Register

LW $t0, 4($s1)
Memory
ที่ Address $s1 + 4 ↓ $t0

ไปเอาข้อมูลจาก Memory แล้วเอามาใส่ $t0

จำคู่นี้ให้แม่น lw = Memory → Register · sw = Register → Memory

MEMORY · SW ⭐⭐⭐

sw — Store Word

sw = Store Word — ตรงข้ามกับ lw คือ เอาข้อมูลจาก Register → Memory

SW $t0, 4($s1)
$t0 ↓ Memory
ที่ Address $s1 + 4

เอาข้อมูลใน $t0 ไปเก็บไว้ใน Memory

lw = Load

Memory → Register — โหลดเข้ามา

sw = Store

Register → Memory — เก็บออกไป

MEMORY · ADDRESSING

Address ใน lw / sw — Base + Offset

⚠️ อย่าอ่านว่า "เอา $s1 + 4 ไปใส่ $t0" — มันคือการหาตำแหน่ง Memory

LW $t0, 4($s1) · วิธีคิด
ใช้ค่าของ $s1 เป็น Base Address
บวก Offset 4 เพื่อหาตำแหน่ง Memory ที่ต้องการ → Memory Address = $s1 + 4
lw → อ่านข้อมูลจาก Address นี้ · sw → เขียนข้อมูลไป Address นี้
ออกข้อสอบบ่อย!โจทย์แบบ trace หน่วยความจำ (เช่น q1t8.asm) ใช้หลักนี้ทั้งข้อ — หา Address ก่อน แล้วค่อยดูค่าที่อ่านได้

ตารางคำสั่ง Byte
คำสั่งความหมายทิศทาง

ARITHMETIC

Arithmetic — add / sub / addi

คำสั่งพื้นฐานสำหรับการคำนวณใน MIPS

add

เอา Register 2 ตัวมาบวกกัน
add $t0,$t1,$t2 → $t0 = $t1 + $t2

sub

ลบ
sub $t0,$t1,$t2 → $t0 = $t1 - $t2

addi

Add Immediate — บวกค่าคงที่
addi $t0,$t1,10 → $t0 = $t1 + 10

สังเกต

add / sub เป็น R-Format · addi เป็น I-Format (มี immediate 16 บิต)

ARITHMETIC · OVERFLOW ⭐⭐⭐

Overflow คืออะไร?

Overflow = ผลลัพธ์มีค่ามากหรือน้อยเกินกว่าที่จำนวน Bit ที่กำหนดเก็บได้

ตัวอย่าง · พื้นที่ 4 bits (สูงสุด 1111 = 15)
15 + 3 = 18 💥

15 + 3 = 18 แต่ 4 bits ไม่สามารถแทนค่า 18 ได้ → เกิด Overflow

บริบทเกิดจากการคำนวณจำนวนเต็มที่มีขนาดจำกัด — หน่วยเก็บมีบิตจำกัด ผลลัพธ์เกินพิกัดจึงล้นออกมา

ARITHMETIC · OVERFLOW

คำสั่งที่ตรวจ Overflow

มีคำสั่งบางตัวที่ ตรวจ Overflow — ถ้าเกิดจะมีการแจ้ง/จัดการตามกลไกของคำสั่ง

add

ตรวจ Overflow

addi

ตรวจ Overflow

sub

ตรวจ Overflow

จำง่าย ๆadd / addi / sub (ไม่มี u) = ตรวจ Overflow — ถ้าเกินพิกัดจะเกิด Exception / แจ้งเตือน

ARITHMETIC · OVERFLOW

SHIFT

Shift คืออะไร?

Shift = การเลื่อนตำแหน่งของ Bit ไปทางซ้ายหรือขวา — มีคำสั่งสำคัญ sll และ srl

ตัวอย่าง · เลื่อนบิต
1001010
← เลื่อนซ้าย 1 ตำแหน่ง (sll)
10010100
จำง่าย ๆ sll → Left ← · srl → Right →

SHIFT · SLL ⭐⭐

sll — Shift Left Logical

เลื่อน Bit ไปทางซ้าย — บิตที่หายไปทางซ้ายตัดทิ้ง เติม 0 ทางขวา

ตัวอย่าง · 0010 → sll 1 → 0100
0010
sll 1 → 2 → 4 (×2)
0100

sll 1 ตำแหน่ง

≈ คูณ 2 — เช่น 2 → 4

sll 2 ตำแหน่ง

≈ คูณ 4 — เช่น 2 → 8

SHIFT · SRL ⭐⭐

srl — Shift Right Logical

เลื่อน Bit ไปทางขวา — เติม 0 ทางซ้ายเสมอ

ตัวอย่าง · 1000 → srl 1 → 0100
1000
srl 1 → 8 → 4 (÷2)
0100
จำง่าย ๆ sll 1 → ประมาณ ×2 · srl 1 → ประมาณ ÷2

SHIFT · SRA ⭐⭐

sra — Shift Right Arithmetic

เลื่อนขวาเหมือน srl แต่ เติมตาม bit เครื่องหมาย (MSB) — คงค่าลบให้เป็นลบ

ตัวอย่าง · 1000 (=-8 signed 4 บิต) → sra 1
1000
sra 1 → เติม 1 (ตาม MSB) → -4
1100

srl (logical)

เติม 0 เสมอ — เหมาะกับค่า unsigned

sra (arithmetic)

เติมตาม bit เครื่องหมาย — ค่า signed ลบยังคงลบ (÷2 โดยประมาณ)

LOGICAL ⭐⭐⭐

Logical — and / or / xor / nor

คำนวณทีละบิต (bitwise) ระหว่าง Register 2 ตัว — หัวใจของข้อสอบบทนี้

TRUTH TABLE · 1 บิต
abandorxornor
000001
010110
100110
111100

จำง่าย ๆ: and = 1 เฉพาะ 1&1 · or = มี 1 ก็ 1 · xor = ต่างกันเป็น 1 · nor = กลับบิตของ or

จับมือทำ · 0x12345678 AND 0xabcd1234
1. จับคู่ทีละหลัก (1 หลัก hex = 4 บิต): 1-2-3-4-5-6-7-8 กับ a-b-c-d-1-2-3-4
2. ไล่ AND ทีละหลัก: 1&a=0, 2&b=2, 3&c=0, 4&d=4, 5&1=1, 6&2=2, 7&3=3, 8&4=0
3. รวมคำตอบ: 0x02041230

เทคนิค: แปลง A-F เป็น 4 บิต (a=1010, b=1011...) แล้ว AND ทีละบิต

nor = NOT(or)

กลับบิตของผล OR — เช่น nor $s2,$s0,$zero = NOT($s0) = complement
ต่อยอด: 2's complement = complement + 1 → addi $s3,$s2,1

xor = ต่างกันเป็น 1

1 เฉพาะเมื่อบิตไม่เท่ากัน — ใช้ตรวจความต่างของข้อมูล

LOGICAL · IMMEDIATE ⭐⭐⭐

andi / ori — immediate logical

เหมือน and / or แต่ใช้ค่าคงที่ (immediate) — ใช้เลือก/ปิดบิตได้

ตัวอย่าง · 0x12345678
andi $t8,$s0,15 — AND กับ 0xf → เอาเฉพาะ 4 บิตล่าง = 0x00000008
ori $t7,$s0,15 — OR กับ 0xf → 4 บิตล่างกลายเป็น f = 0x1234567f
ออกข้อสอบ!andi ใช้เป็น mask — เลือกบิตที่ต้องการ (1) และปิดบิตที่ไม่ต้องการ (0) เช่น 0x3fff เก็บบิต 0-13

PSEUDO-INSTRUCTION

li — Load Immediate

li = ใส่ค่าคงที่ (immediate) ลง Register — ใช้ตั้งค่าเริ่มต้นในโปรแกรม

ตัวอย่าง
li $s0, 0x12345678 → $s0 = 0x12345678
จริง ๆ แล้วli เป็น pseudo-instruction — ตัว assembler จะแปลงเป็น addiu / lui+ori ให้อัตโนมัติ แต่เราเขียน li ได้สะดวกกว่า

NUMBER SYSTEMS

Signed vs Unsigned — ตัว u สำคัญมาก

Signed มีค่าติดลบได้ · Unsigned ไม่มีค่าติดลบ — จึงมีคำสั่งแยกสองแบบ

SIGNED · มีค่าลบ
เช่น -10, 0, 10
ใช้ MSB (บิตซ้ายสุด) เป็นเครื่องหมาย
0xabcd1234 แบบ signed = ค่าลบ
UNSIGNED · ไม่มีค่าลบ
เช่น 0, 1, 2, ...
ใช้บิตทั้งหมดแทนค่า
0xabcd1234 แบบ unsigned = 2,882,343,476
จำแบบนี้ถ้าเจอ addu · addiu · subu · sltu · sltiu ให้สังเกตตัว u — หมายถึง Unsigned

COMPARE ⭐⭐⭐

slt / sltu / sltiu — เปรียบเทียบ

ผลลัพธ์เป็น 1 ถ้า "น้อยกว่า" จริง ไม่งั้นเป็น 0 — ต่างกันที่ signed / unsigned / immediate

จับมือเปรียบเทียบ · 0x12345678 vs 0xabcd1234
1. ดูว่าเป็น signed หรือ unsigned — ดูตัว u ในชื่อคำสั่ง
2. slt (signed): 0xabcd1234 มี MSB = 1 → เป็นค่าลบ — บวก < ลบ? ไม่จริง → 0
3. sltu (unsigned): 0xabcd1234 = 2.88 พันล้าน, 0x12345678 = 305 ล้าน — 305M < 2.88B? จริง → 1
4. sltiu (unsigned + immediate): 2.88 พันล้าน < 9? ไม่จริง → 0
ตารางสรุป
คำสั่งความหมายตัวอย่างผล
sltsigned: $rs < $rtบวก < ลบ?0
sltuunsigned: $rs < $rt305M < 2.88B?1
sltiuunsigned: $rs < immediate2.88B < 9?0
จุดพลาดยอดฮิตตัวเลข hex ตัวเดียวกัน slt มองเป็นลบ (0xabcd1234 = -1.4 พันล้าน) แต่ sltu มองเป็นบวก (2.88 พันล้าน) → คำตอบต่างกัน!

EXAM FOCUS ⭐⭐⭐

เรื่องที่น่าจะออกสอบ

เช็คตัวเองก่อนสอบ — ตอบได้ครบก็พร้อมลุยข้อสอบท้ายบท

and / or / xor / nor — คำนวณทีละบิตได้ (รู้จัก hex ต่อบิต: a AND 1 = 1&a=0, 2&b=2, ...)
sll / srl / sra — เลื่อนซ้าย ×2, เลื่อนขวา ÷2, sra เติมตามเครื่องหมาย
andi / ori — ใช้ immediate เป็น mask เช่น 15 = 0xf, 0x3fff = เก็บบิต 0-13
slt / sltu / sltiu — signed vs unsigned เปลี่ยนผลลัพธ์ (0xabcd1234: ลบ vs บวก)
nor กับ $zero = complement · complement + 1 = 2's complement
