ISA คืออะไร?

ISA = Instruction Set Architecture — พูดง่าย ๆ คือ กฎ / ภาษาที่ใช้บอก CPU ว่าให้ทำอะไร

ทำไมต้องมี ISA

CPU ไม่เข้าใจภาษา C, Java หรือ Python โดยตรง — โปรแกรมจะถูกแปลงลงมาเป็นคำสั่งระดับต่ำที่ CPU เข้าใจ

นิยามแบบวิชาการ

ISA = Instruction Set Architecture — ชุดคำสั่งทั้งหมดที่ CPU รองรับ พร้อมกฎวิธีการใช้งาน

จำง่าย ๆISA เป็นเหมือน ตัวกลางระหว่าง Software กับ Hardware — ซอฟต์แวร์พูดภาษา ISA แล้ว CPU ก็ทำตามได้

NUMBER SYSTEMS · BINARY

เลขฐานสอง (Binary) — ทีละขั้นจากศูนย์

ระบบเลขที่เราใช้ทุกวันคือ Decimal (ฐาน 10) แต่คอมพิวเตอร์เก็บข้อมูลเป็น Binary (ฐาน 2) — มีตัวเลขแค่ 0 กับ 1

หลักคิด · เลขทุกตำแหน่งมี "ค่า" ของมัน
Decimal ใช้ตัวเลข 10 ตัว (0–9) — แต่ละตำแหน่งคูณ 10: 258 = 2×100 + 5×10 + 8×1
Binary ใช้ตัวเลขแค่ 2 ตัว (0, 1) — แต่ละตำแหน่งคูณ 2: หลัก 8 | 4 | 2 | 1 (คือ 2³, 2², 2¹, 2⁰)
บิตที่เป็น 1 = เอามาบวก · บิตที่เป็น 0 = ข้ามไป
ตัวอย่างแรก · 1011₂ มีค่าเท่าไหร่?
เขียนบิตเรียง: 1 0 1 1 แล้ววางค่าประจำตำแหน่งข้างใต้: 8 | 4 | 2 | 1
เอาเฉพาะตำแหน่งที่มีบิต 1: 1×8 + 0×4 + 1×2 + 1×1
บวกกัน: 8 + 0 + 2 + 1 = 11
ฝึกอ่าน ง่าย → กลาง → ยาก · ใช้ค่าประจำตำแหน่ง 8|4|2|1 เหมือนเดิมทุกข้อ
🟢 ง่าย: 0011 = 0+0+2+1 = 3 · 0101 = 0+4+0+1 = 5
🟡 กลาง: 1100 = 8+4+0+0 = 12 · 1010 = 8+0+2+0 = 10
🔴 ยาก: 1111 = 8+4+2+1 = 15 (ค่าเต็ม 4 บิต) · ขยายเป็น 8 บิต: 11111111 = 128+64+32+16+8+4+2+1 = 255
นับเลขแบบคอมพิวเตอร์ · เริ่มจาก 0 ขึ้นไป
0, 1 → 2 = 10 (หมดเลขให้ใช้แล้ว จึงทดขึ้นหลักถัดไป เหมือน 9→10)
3 = 11 → 4 = 100 → 5 = 101 → 6 = 110 → 7 = 111
สังเกต: พอครบ 2 บิต (11) ต้องเพิ่มเป็น 3 บิต (100) — 1 บิตเพิ่ม = จำนวนแบบเพิ่ม 2 เท่า เสมอ
แปลงกลับ · Decimal → Binary (วิธีลบ 2^N ที่ใหญ่สุดทีละตัว)
ตัวอย่าง: 13 → 2³=8 ใหญ่สุดที่ยังไม่เกิน → เอา 1 ที่หลัก 8: 13−8 = 5
2²=4 ใหญ่สุดที่ยังไม่เกิน 5 → เอา 1 ที่หลัก 4: 5−4 = 1 → 2¹=2 เกิน 1 → 0 ที่หลัก 2

NUMBER SYSTEMS

เลขฐาน 2 / 10 / 16 — แปลงไปมาให้คล่อง

คอมพิวเตอร์เก็บข้อมูลเป็นเลขฐาน 2 (0/1) แต่เขียนยาวมาก จึงย่อด้วย Hex (ฐาน 16) — กติกาที่ต้องจำขึ้นใจ: 1 หลัก Hex = 4 บิต พอดี

ตัวอักษร Hex ที่ต้องแปลงให้ได้ทันที

A = 10B = 11C = 12D = 13E = 14F = 15
ทิศที่ 1 · Hex → Decimal · 0xFA = เท่าไหร่?
1. แยกหลัก: 0xFA มี 2 หลัก คือ F กับ A
2. แปลงตัวอักษรเป็นเลข: F = 15, A = 10
3. หลักซ้าย (F) มีค่าตำแหน่งเป็น ×16: 15 × 16 = 240
4. หลักขวา (A) บวกตามหลังตรง ๆ: 240 + 10 = 250
5. คำตอบ: 0xFA = 250 ✅
ทิศที่ 2 · Hex → Binary (เร็วสุด) · 0xFA
1. แปลงทีละหลัก หลักละ 4 บิต: F = 1111, A = 1010
2. เอามาต่อกัน: 1111 1010
3. คำตอบ: 0xFA = 111110102 ✅
11111010

วิธีนี้เร็วกว่าการแปลงผ่าน Decimal มาก — ใช้ได้ทุกครั้งที่โจทย์ให้ Hex มา

ทิศที่ 3 · Binary → Decimal (บวกตามค่าตำแหน่ง) · 11111010
1. เขียนค่าตำแหน่งของแต่ละบิตจากขวาไปซ้าย: 128, 64, 32, 16, 8, 4, 2, 1 (คือ 27 ถึง 20)
2. บวกเฉพาะตำแหน่งที่เป็นบิต 1: 128+64+32+16+8+0+2+0
3. รวมผล: 128+64+32+16+8+2 = 250 ✅
ทิศที่ 4 · Decimal → Hex · 196 = เท่าไหร่ในฐาน 16?
1. เอา 196 ÷ 16 = 12 เศษ 4 → หลักขวา = 4, ผลหาร 12 = C
2. เอาผลหาร (12) ÷ 16 = 0 เศษ 12 → หลักซ้าย = C
3. อ่านผลหารจากล่างขึ้นบน: 196 = 0xC4 ✅

ตรวจคำตอบย้อนกลับ: 0xC4 → C=12×16=192, +4 = 196 ✅ ตรงกัน

🧮 วิธีใช้เครื่องคิดเลข (BASE-N)

เครื่องคิดเลขวิทยาศาสตร์บางรุ่นมีโหมด BASE-N หรือ DEC/HEX/BIN — พิมพ์เลขแล้วกดสลับโหมดจะแปลงให้อัตโนมัติ แต่ ในห้องสอบอาจใช้ไม่ได้ จึงต้องทำมือเป็นเสมอ ตามขั้นตอนด้านบน

จำแบบนี้32 bits = 8 หลัก Hex · 4 bits = 1 หลัก Hex เสมอ · 0x ข้างหน้า = บอกว่าเป็นเลขฐาน 16 · A-F = 10-15

Unsigned แปลว่า "ไม่มีเครื่องหมาย" — ทุกบิตถูกใช้แทนขนาดของตัวเลขล้วน ๆ ไม่มีบิตไหนถูกกันไว้ทำเครื่องหมายลบ ดังนั้นค่าที่เก็บได้จึงเริ่มจาก 0 เสมอ

อธิบายก่อนคำนวณ: ทำไมสูตรถึงเป็น 0 .. 2N-1
N บิต เก็บได้ 2N แบบ (จากสไลด์ก่อนหน้า) — ระบบ unsigned เอาทุกแบบไปแทนเลข 0, 1, 2, 3, ... เรียงขึ้นไปเรื่อย ๆ
เริ่มนับจาก 0 (ไม่ใช่ 1) ดังนั้นค่ามากสุดจึงเป็นแบบที่ 2N ซึ่งอยู่ที่ตัวเลข 2N - 1 (ลบ 1 เพราะเริ่มนับที่ 0)
สรุปสูตร: น้อยสุด = 0 · มากสุด = 2N - 1
🎯 ตัวอย่างแบบข้อสอบ · N = 6-bit unsigned มากสุด/น้อยสุด?
1. อ่านโจทย์: unsigned, N = 6
2. หา 2N ก่อน: 26 = 64
3. มากสุด = 64 - 1 = 63 · น้อยสุด = 0
4. คำตอบ: มากสุด = 63, น้อยสุด = 0

🧮 เครื่องคิดเลข: 2 → ^ → 6 → = ได้ 64 แล้วลบ 1 ด้วยมือ

ความเข้าใจ: เราต้องหา N บิต (unsigned) ที่เก็บค่าได้ครอบคลุมตัวเลขสูงสุดที่โจทย์ต้องการ นั่นคือหา N ที่เล็กที่สุดซึ่งทำให้ 2N - 1 ≥ ค่าสูงสุด

2. ลองบิตถัดไป: 234 ≈ 17,179,869,184 (1.7 หมื่นล้าน — มากพอที่จะครอบคลุมแล้ว)

NUMBER SYSTEMS

Signed Range, MSB และ Sign Bit

Signed แปลว่า "มีเครื่องหมาย" — เก็บค่าลบได้ด้วย โดยยอม "เสีย" บิตซ้ายสุด 1 บิต ไปทำหน้าที่บอกเครื่องหมาย แทนที่จะใช้เก็บขนาดของตัวเลข

อธิบายก่อนคำนวณ: ทำไมต้องเสีย 1 บิต และทำไมสูตรไม่สมมาตร
MSB (Most Significant Bit) คือบิตซ้ายสุดของเลขฐาน 2 — ในระบบ signed บิตนี้ถูกเรียกว่า Sign Bit: ถ้า MSB = 0 → เป็นบวก, ถ้า MSB = 1 → เป็นลบ
เมื่อ 1 บิต (MSB) ถูกกันไว้ทำเครื่องหมายแล้ว จะเหลือ N-1 บิต ไปเก็บขนาดของตัวเลข ซึ่งเก็บได้ 2N-1 แบบ
ฝั่งบวก (รวม 0) ใช้ไป 2N-1 แบบ แต่เริ่มนับที่ 0 → มากสุด = 2N-1 - 1
ฝั่งลบ ไม่ต้องเก็บ 0 ซ้ำ จึงได้ครบ 2N-1 แบบเต็ม ๆ → น้อยสุด = -2N-1 (ฝั่งลบมากกว่าฝั่งบวกอยู่ 1 ค่าเสมอ — นี่คือเหตุผลที่ Range ไม่สมมาตร)

Minimum = -2N-1ค่าลบน้อยสุด (ติดลบมากสุด)

3. แทนค่า: 2(6-1) - 1 = 25 - 1

Two's Complement — แปลงเป็นค่าลบ (ไปและกลับ)

Two's Complement คือวิธีมาตรฐานที่คอมพิวเตอร์ใช้เก็บเลขลบ — วิธีสร้าง: กลับบิตทุกตัว (invert) แล้วบวก 1 เข้าไป

ขั้นตอน (ไปทาง) · หา -6 ในระบบ 8 บิต
1. เขียน 6 (ค่าบวก) เป็น binary 8 บิตก่อน: 00000110
2. Invert — กลับบิตทุกตัว (0↔1): 11111001
3. บวก 1 เข้าไป: 11111001 + 1 = 11111010
4. คำตอบ: 11111010 = 0xFA = -6
ขั้นตอน (กลับทาง) · 11111011 คือค่าลบอะไร?
1. ดู MSB: เป็น 1 → เป็นค่าลบแน่นอน ต้องหา "ขนาด" (magnitude) ของมัน
2. Invert ทุกบิต: 11111011 → 00000100
3. บวก 1: 00000100 + 1 = 00000101 = 5 (ฐาน 10)
4. คำตอบ: 11111011 = -5 ✅ (ทำ invert+1 ซ้ำสองรอบ จะย้อนกลับมาที่ค่าเดิมเสมอ)
🚀 ทางลัด: อ่าน Hex เป็น Signed โดยไม่ต้อง invert+1
สูตรลัด: ถ้า MSB = 1 (เลข Hex หลักแรก ≥ 8) → ค่า signed = ค่า unsigned - 2N
ตัวอย่าง 1: 0xFA (8-bit) → unsigned = 250 → MSB=1 → signed = 250 - 256 = -6 ✅ ตรงกับวิธี invert+1 ด้านบน
ตัวอย่าง 2: 0xC8 (8-bit) → unsigned = 200 → MSB=1 (C ≥ 8) → signed = 200 - 256 = -56
ตัวอย่าง 3: 0xC4 (8-bit) → unsigned = 196 → MSB=1 (C ≥ 8) → signed = 196 - 256 = -60

วิธีลัดนี้เร็วกว่ามากในห้องสอบ — ใช้ได้เฉพาะตอนแปลง "unsigned → signed" ของบิตแพทเทิร์นเดียวกันเท่านั้น

บิตเดียวกัน ความหมายต่างกัน

0xFA = 250 (unsigned 8 บิต) แต่ = -6 (signed 8 บิต) — เก็บในหน่วยความจำเหมือนกันทุกประการ ต่างแค่วิธีตีความ

เมื่อค่าลบใหญ่เกินจะแทนใน Hex ไม่ได้

ถ้าโจทย์ให้แปลงค่าลบที่ ต่ำกว่า -2N-1 เป็น Hex เช่น -140 ในระบบ 8-bit signed (ช่วง -128..127) → -140 ต่ำกว่า -128 → แทนค่าไม่ได้ ตอบ ERR

Exam Tipเจอเลข Hex ที่หลักแรก ≥ 8 (8,9,A,B,C,D,E,F) ในระบบ signed → MSB=1 แน่นอน → ลองลบ 2N ก่อนเสมอ (8-bit ลบ 256, 32-bit ลบ 4,294,967,296)

NUMBER SYSTEMS · ARITHMETIC

บวก-ลบเลข Signed/Unsigned Overflow และ ERR

โจทย์แนวนี้คือแนวที่ออกสอบมากที่สุด — ทำตามอัลกอริทึม 3 ขั้นตอนนี้ทุกครั้ง แล้วทุกข้อจะกลายเป็นเรื่องง่าย

🎯 วิธีทำในห้องสอบ · Algorithm 3 ขั้นตอน ใช้ได้กับทุกข้อ
1. คำนวณผลก่อน (เหมือนเลขคณิตปกติ) — ไม่ต้องสนใจ N บิตตอนนี้ เช่น -125-10 = -135, 200+70 = 270
2. เช็ค Operand (ตัวเลขในโจทย์เอง) — ถ้าตัวเลขที่โจทย์ให้มาตัวใดตัวหนึ่งเกินช่วงของระบบนั้นอยู่แล้ว → ตอบ ERR ทันที ไม่ต้องคำนวณต่อ
3. เช็คผลลัพธ์ — ถ้า operand ทุกตัวอยู่ในช่วงแล้ว แต่ผลลัพธ์จากขั้น 1 เกินช่วง → เกิด Wrap Around: บวกหรือลบด้วย 2N จนกว่าจะกลับเข้าช่วง
ทำไมต้อง Wrap Around · หน่วยความจำมีแค่ N บิต เก็บได้แค่ 2N แบบ
ตัวอย่าง: 8-bit unsigned: 200 + 70
1. คำนวณตรง ๆ: 200 + 70 = 270
2. แต่ 8-bit unsigned เก็บได้แค่ 0 ถึง 255 เท่านั้น (256 แบบ) — 270 เกินไป
3. ตัวเลขที่เกินจะ "ล้น" ออกไป เหลือแค่ส่วนที่พอดีกับ 8 บิต — คำนวณด้วย modulo 256: 270 mod 256 = 14
4. คำตอบ: 14

🧮 วิธีใช้เครื่องคิดเลขหา mod

ถ้าเครื่องมีปุ่ม mod: กด 270 → mod → 256 → = ได้ 14 ทันที
ถ้าไม่มี ให้ทำมือ: 270 ÷ 256 = 1.05... ปัดเศษทิ้ง เหลือ 1 → 270 - (1×256) = 14

Wrap Around ฝั่งลบ · 70 - 200

8-bit unsigned: 70 - 200 = -130 ทางคณิตศาสตร์ แต่ unsigned เก็บค่าลบไม่ได้ ผลจึงวนกลับมาบวกด้วย 256: -130 + 256 = 126 ✅

🎯 ตัวอย่างแบบข้อสอบทีละขั้น · 8-bit signed: -125 - 10
1. Range ของระบบ: signed 8-bit = -128 ถึง 127
2. เช็ค operand: -125 และ 10 อยู่ในช่วง -128..127 ทั้งคู่ → ผ่าน ยังไม่ ERR
3. คำนวณ: -125 - 10 = -135
4. เช็คผลลัพธ์: -135 ต่ำกว่า -128 → เกินช่วง → เกิด Overflow ต้อง Wrap Around
5. Wrap Around: บวกด้วย 28 = 256: -135 + 256 = 121
6. คำตอบ: 121 (ค่าอยู่ในช่วง -128..127 แล้ว ✅ ตรวจผ่าน)
Hex Addition · บวกเลข Hex ได้ 2 วิธี · 0xFA + 0x25 (8-bit unsigned)

วิธีที่ 1 · บวกในฐาน Hex ตรง ๆ

FA + 25 = 11F (บวกแบบ Hex, ทดหลักแบบฐาน 16)
8-bit เก็บได้แค่ 2 หลัก Hex (8 บิต) — 11F มี 3 หลัก เกินมา 1 หลัก (256) ตัดหลักที่เกินทิ้ง → เหลือ 0x1F

วิธีที่ 2 · แปลงเป็น Decimal ก่อน (แนะนำ — ผิดพลาดยากกว่า)

0xFA = 250, 0x25 = 37
250 + 37 = 287 → เกิน 255 → 287 mod 256 = 31

32-BIT NUMBERS

ระบบ 32 บิต — ช่วงกว้างกว่า กติกาเหมือนเดิม

หลักการทุกอย่างเหมือน 8 บิตทุกประการ — ต่างกันแค่ช่วงใหญ่ขึ้นมาก และจำไว้ว่า 1 หลัก Hex = 4 บิต ดังนั้น 8 หลัก Hex = 32 บิตพอดี

ช่วงของ 32 บิต (จำคู่กันให้ขึ้นใจ)
Unsigned: 0 ถึง 4,294,967,295 (= 2³² − 1 = 0xFFFFFFFF)
Signed: −2,147,483,648 ถึง 2,147,483,647 (= −2³¹ ถึง 2³¹−1)
2³² = 4,294,967,296 — "เลขกลม" ที่ใช้ลบเมื่อเกิด wrap แบบ 32 บิต (เหมือน 256 ของ 8 บิต)
🎯 ตัวอย่างแบบข้อสอบ · 0xFFFFFFFB + 0x00000007 (unsigned 32 บิต)
1. อ่านค่า: 0xFFFFFFFB = 4,294,967,291 — วิธีลัด: 0xFFFFFFFB = 2³² − 5 (เพราะ FB = 251 = 256−5)
2. บวก: 4,294,967,291 + 7 = 4,294,967,298
3. เช็คช่วง: 4,294,967,298 > 4,294,967,295 → เกิน → wrap: ลบ 2³²
4. 4,294,967,298 − 4,294,967,296 = 2
วิธีลัดด้วย Hex · ไม่ต้องแตะเครื่องคิดเลขเลย
บวก hex ตรง ๆ: 0xFFFFFFFB + 0x00000007 = 0x1_00000002 (หลักเกินมา 1 ตัว = บิตที่ 33)
32 บิตจุได้ 8 หลัก Hex → ตัดหลักเกิน (ตัว 1 หน้า) ทิ้ง → เหลือ 0x00000002
ดังนั้นคำตอบ = 2 ✅ ตรงกับวิธี decimal ทุกประการ
ตีความแบบ signed · เลขที่ขึ้นต้น f…
0xFFFFFFFB มี MSB = 1 (F = 1111) → ถ้าตีความแบบ signed = 4,294,967,291 − 2³² = −5
ดังนั้น signed 32-bit: 0xFFFFFFFB = −5 และ 0xFFFFFFFF = −1 (เหมือน 0xFF = −1 ใน 8 บิต)
เทคนิค: เลขที่หลักแรก ≥ 8 ในระบบ signed → ลบ 2N เสมอ (32 บิตลบ 4,294,967,296)
Exam Tipเห็นเลข hex ยาว 8 หลัก ให้อ่าน "ห่างจากขอบเท่าไหร่" แทนการแปลงเต็มรูปแบบ — เช่น 0xFFFFFFFB = 2³²−5, 0x00000007 = 7 → บวกกันได้ 2 ทันทีโดยไม่ต้องกดเลขใหญ่

ต่อจากหน้าเฉลยข้อ 1–10 — ช่วงนี้เป็น Hex, การแปลง และ 32 บิต เปิดทีละข้อ แล้วเทียบกับคำตอบของคุณว่าถูกหรือยัง

ส่วนที่สาม · Hex และการแปลง (ข้อ 11–16)
ข้อ 11 · unsigned 8 บิต: 0xFA = ? (ตอบ decimal)
🎯 ให้: 0xFA, unsigned 8 บิต · ถาม: ค่า decimal
ขั้น: F=15, A=10 → 15×16 + 10
🧮 15 × 16 = 240 → + 10 =
✔ 250 · เทคนิค: Hex → Decimal = (หลักแรก × 16) + หลักสอง · เช็ค 250 ≤ 255 ✓
ข้อ 12 · signed 8 บิต: 0xFA = ? (ตอบ decimal)
🎯 ให้: 0xFA, signed 8 บิต · ถาม: ค่า decimal
ขั้น: unsigned ก่อน = 250 → MSB = 1 (F = 1111) → เป็นค่าลบ
🧮 250 − 256 =
✔ −6 · เทคนิค: หลักแรก ≥ 8 → signed = unsigned − 2N
ข้อ 13 · unsigned 8 บิต: 0xFA + 0x25 = ? (ตอบ decimal)
🎯 ให้: unsigned 8 บิต · ถาม: ผลบวก
ขั้น: 0xFA=250, 0x25=2×16+5=37 → 250+37 = 287 → เกิน 255 → wrap
🧮 15×16+10 = 250 → + 37 = 287 → − 256 =
✔ 31 · เทคนิค: แปลงเป็น decimal ก่อนเสมอ แล้วค่อยเช็ค wrap (ลัด: บวก hex ได้ 0x11F → ตัดหลักเกิน → 0x1F = 31)
ข้อ 14 · เลข decimal 10 หลัก ต้องใช้กี่บิต?
🎯 ให้: เลข 10 หลัก · ถาม: จำนวนบิต n ที่พอ
ขั้น: เลข 10 หลักมากสุด = 9,999,999,999 → 2³³ = 8,589,934,592 ยังไม่พอ → 2³⁴ = 17,179,869,184 พอ
🧮 2¹⁰=1024 → 2²⁰=1,048,576 → 2³⁰=1,073,741,824 → คูณ 2 ไปเรื่อย ๆ: 2³³ → 2³⁴
✔ 34 บิต · เทคนิค: หา n ที่ 2n "เพิ่งเกิน" ค่ามากสุด — ไม่ใช่จำเลข 34 แต่มารู้ที่มาของมัน
ข้อ 15 · signed 8 บิต: −140 เขียนเป็น Hex?
🎯 ให้: signed 8 บิต · ถาม: รูปแบบ hex
ขั้น: เช็คช่วง −128..127 → −140 ต่ำกว่า −128 → เก็บด้วย 8 บิตไม่ได้
🧮 ไม่ต้องคำนวณ
✔ ERR · เทคนิค: ค่าเกินช่วงตั้งแต่แรก → ตอบ ERR ไม่ใช่ไปแปลงเลข
ข้อ 16 · unsigned 8 บิต: −140 เขียนเป็น Hex?
🎯 ให้: unsigned 8 บิต · ถาม: รูปแบบ hex
ขั้น: unsigned เก็บค่าลบไม่ได้ → −140 เกินช่วง 0..255
🧮 ไม่ต้องคำนวณ
✔ ERR · เทคนิค: ค่าลบใน unsigned = ERR — เหมือนข้อ 15 แต่เหตุผลคนละแบบ
ส่วนที่สี่ · 32 บิต และ Hex บวก-ลบ (ข้อ 17–20)
ข้อ 17 · unsigned 32 บิต: 0xFFFFFFFB + 0x00000007 = ? (ตอบ decimal)
🎯 ให้: unsigned 32 บิต (ช่วง 0..4,294,967,295) · ถาม: ผลบวก
ขั้น: 0xFFFFFFFB = 2³² − 5 = 4,294,967,291 → +7 = 4,294,967,298 → เกิน 2³²−1 → wrap
🧮 4,294,967,291 + 7 = 4,294,967,298 → − 4,294,967,296 =
✔ 2 · เทคนิคลัด: 0xFFFFFFFB + 0x00000007 = 0x1_00000002 → ตัดหลักเกิน 8 หลัก → 0x00000002 = 2
ข้อ 18 · unsigned 32 บิต: 0xFFFFFFFB + 0x00000007 = ? (ตอบ decimal)
🎯 ให้: โจทย์ซ้ำกับข้อ 17 เป๊ะ ๆ
ขั้น: วิธีคิดเหมือนข้อ 17 ทุกประการ
✔ 2 · เทคนิค: เจอโจทย์ซ้ำ อย่าตกใจ — ตรวจระบบกับจำนวนบิตให้ดีก่อนตอบเหมือนเดิม
ข้อ 19 · unsigned 8 บิต: 0xC8 + 0xC4 = ? (ตอบ decimal)
🎯 ให้: unsigned 8 บิต · ถาม: ผลบวก
ขั้น: 0xC8 = 12×16+8 = 200, 0xC4 = 12×16+4 = 196 → 200+196 = 396 → เกิน 255 → wrap
🧮 12×16+8 = 200 → + 196 = 396 → − 256 =
✔ 140 · เทคนิคลัด: บวก hex ตรง ๆ 0xC8+0xC4 = 0x18C → ตัดหลักเกิน → 0x8C = 8×16+12 = 140
ข้อ 20 · signed 8 บิต: 0xC8 + 0xC4 = ? (ตอบ decimal)
🎯 ให้: signed 8 บิต · ถาม: ผลบวก
ขั้น: MSB = 1 ทั้งคู่ → 0xC8 = 200−256 = −56, 0xC4 = 196−256 = −60 → −56 + −60 = −116
🧮 200−256 = −56 → 196−256 = −60 → −56 + −60 =
✔ −116 · เทคนิค: −116 อยู่ในช่วง −128..127 → ไม่ wrap, ไม่ ERR — บิตเดียวกันกับข้อ 19 แต่ระบบต่างกัน คำตอบต่างกัน
