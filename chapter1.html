FUNDAMENTAL CONCEPTS

ISA คืออะไร?

ISA = Instruction Set Architecture — พูดง่าย ๆ คือ กฎ / ภาษาที่ใช้บอก CPU ว่าให้ทำอะไร

FLOW · ภาษาถูกแปลงลงมาเป็นระดับ CPU
ภาษา C ภาษาโปรแกรมระดับสูง
Assembly ภาษาใกล้เครื่อง
Machine Language ภาษาเครื่อง · Binary
CPU 💻 ทำงานตามคำสั่ง

ทำไมต้องมี ISA

CPU ไม่เข้าใจภาษา C, Java หรือ Python โดยตรง — โปรแกรมจะถูกแปลงลงมาเป็นคำสั่งระดับต่ำที่ CPU เข้าใจ

นิยามแบบวิชาการ

ISA = Instruction Set Architecture — ชุดคำสั่งทั้งหมดที่ CPU รองรับ พร้อมกฎวิธีการใช้งาน

จำง่าย ๆISA เป็นเหมือน ตัวกลางระหว่าง Software กับ Hardware — ซอฟต์แวร์พูดภาษา ISA แล้ว CPU ก็ทำตามได้

FUNDAMENTAL CONCEPTS

Stored-Program Concept

แนวคิดสำคัญของคอมพิวเตอร์ — ทั้ง "ข้อมูล" และ "คำสั่งโปรแกรม" เก็บอยู่ใน Memory ได้

MEMORY (RAM) · มีทั้งคำสั่งและข้อมูล

0x0004

ใน RAM อาจมีทั้งสองอย่าง

ทั้งคำสั่งโปรแกรม (Instruction) และข้อมูล (Data) ถูกเก็บไว้ในหน่วยความจำเดียวกัน เช่น RAM

CPU ทำทีละคำสั่ง

CPU จะอ่านคำสั่งจาก Memory แล้วทำตามทีละคำสั่ง — แนวคิดนี้เรียกว่า Stored-Program Concept

Exam Tipข้อสอบชอบถามว่า "Stored-Program หมายถึงอะไร" — ตอบว่า โปรแกรมและข้อมูลถูกเก็บไว้ใน Memory เดียวกัน

CPU INTERNALS

CPU รู้ได้อย่างไรว่าต้องทำคำสั่งไหน?

ตรงนี้ต้องรู้จัก PC — PC = Program Counter เป็น Register ที่เก็บ Address ของคำสั่งที่ CPU จะทำ

LIVE DEMO · กดปุ่มเพื่อดู PC ขยับทีละคำสั่ง

PC ชี้ไปที่คำสั่ง

CPU เห็น PC = 1000 ก็รู้ว่า "ต้องไปเอาคำสั่งที่ Address 1000 มาทำ"

แล้ว PC ก็ขยับต่อ

หลังจากทำคำสั่งนั้นแล้ว PC จะเปลี่ยนไปยังคำสั่งถัดไป — คำสั่ง MIPS มีขนาด 4 bytes จึงมักขยับทีละ 4

จำแบบนี้PC = "เข็มชี้ตำแหน่ง" ของ CPU — บอกว่าตอนนี้ต้องอ่านคำสั่งจาก Address ไหน

แล้ว MIPS คืออะไร?

MIPS เป็นตัวอย่างของ ISA ที่ใช้เรียน Computer Architecture — จุดสำคัญคือคำสั่งมีขนาด 32 bits หรือ 4 bytes

MIPS คือตัวอย่าง ISA

MIPS ใช้กันแพร่หลายในห้องเรียน Computer Architecture เพราะเข้าใจง่าย และเป็นพื้นฐานของ ISA จริงในตลาด

32 bits = 4 bytes

คำสั่ง MIPS หนึ่งคำสั่งมีขนาด 32 bits พอดี ซึ่งเท่ากับ 4 bytes — ตัวเลขนี้จะโผล่ขึ้นมาเรื่อย ๆ ทั้งบท

MACHINE LANGUAGE

ทำไมต้องมี Assembly? 😅

สมมติเราอยากบอก CPU ว่า "เอา A + B" — ถ้าเขียนเป็น Binary จะอ่านยากมาก

เปรียบเทียบ · Binary vs Assembly
Binary · อ่านยาก 00000001001010100100000000100000
→
Assembly · อ่านง่าย add $t0, $t1, $t2

มนุษย์อ่านลำบากมาก 😅 → ภาษา Assembly จึงช่วยให้อ่านเข้าใจง่ายกว่า

Assembly หมายถึงประมาณว่า

add $t0, $t1, $t2 = $t0 = $t1 + $t2

แล้วแปลงเป็น Machine Language

จากนั้น Assembly จะถูกแปลงเป็น Machine Language ซึ่งเป็น Binary ให้ CPU ใช้งานจริง

INSTRUCTIONS

Instruction คืออะไร?

Instruction = คำสั่ง — แต่ละคำสั่งบอก CPU ว่าให้ทำอะไร เช่น

add บวก sub ลบ lw โหลดจาก Memory sw เก็บลง Memory beq กระโดดถ้าเท่ากัน

นำข้อมูลใน $t1 + ข้อมูลใน $t2 → เก็บผลลัพธ์ไว้ที่ $t0

แต่ละคำสั่งมีความหมายชัดเจน

add = บวก, sub = ลบ, lw = โหลดจาก Memory, sw = เก็บลง Memory, beq = กระโดดถ้าค่าเท่ากัน

Exam Tipข้อสอบชอบให้จับคู่ — จำว่า lw = Load (อ่าน), sw = Store (เขียน) ลง Memory

MIPS กำหนดให้ Instruction มีขนาดคงที่ — 1 Instruction = 32 bits = 4 bytes

1 Instruction = 32 bits

ข้อดีของขนาดคงที่

CPU สามารถรู้ได้ง่ายว่าคำสั่งหนึ่งกินพื้นที่เท่าไหร่ — จึงอ่านคำสั่งจาก Memory ได้อย่างเป็นระบบ

ตัวอย่าง

NUMBER SYSTEMS

เลขฐาน 2 และ Hexadecimal

คอมพิวเตอร์เก็บข้อมูลเป็นเลขฐาน 2 (0/1) — แต่เขียนยาวมาก เราจึงใช้ Hex (ฐาน 16) ให้สั้นลง: 1 หลัก Hex = 4 บิต

จับมือแปลง · 0xfa = เท่าไหร่? (ตอบฐาน 10)
1. แยกหลัก: 0xfa มี 2 หลัก คือ f กับ a
2. แปลงตัวอักษร: f = 15, a = 10 (จำ A=10, B=11, C=12, D=13, E=14, F=15)
3. หลักแรก (f) คูณ 16: 15 × 16 = 240
4. หลักที่สอง (a) บวกตามหลัง: 240 + 10
5. ได้คำตอบ: 0xfa = 250 ✅
11111010

f = 1111, a = 1010 → 1111 1010 (2) = 0xfa — 1 หลัก Hex = 4 บิต

เลขฐานที่เจอบ่อย

Binary — ฐาน 2 ใช้บิต 0/1
Hex — ฐาน 16 ใช้ 0-9, A-F หนึ่งหลักแทน 4 บิต
Decimal — ฐาน 10 ที่มนุษย์ใช้ปกติ

ทำไมต้องรู้ Hex

คำสั่ง MIPS 32 bits ยาวเกินไป ถ้าเขียนเป็น 8 หลัก Hex จะกระชับกว่า — เช่น 0x012A4020

จำแบบนี้32 bits = 8 หลัก Hex · 4 bits = 1 หลัก Hex · 0x ข้างหน้า = เลขฐาน 16 · A-F = 10-15

NUMBER SYSTEMS

Signed vs Unsigned — ช่วงค่าของ N บิต

บิตจำนวนเดียวกัน ตีความได้ 2 แบบ — Unsigned ไม่มีค่าลบ · Signed มีค่าลบ (ใช้บิตซ้ายสุดเป็นเครื่องหมาย)

จับมือหา ช่วงค่า (Range) · N = 6 บิต
1. คำนวณ 2^6 = 64 ไว้ก่อน
2. Unsigned มากสุด = 2^N - 1 = 64 - 1 = 63 · น้อยสุด = 0
3. Signed แบ่งครึ่ง: บวก = 0 .. 2^(N-1)-1 = 32-1 = 31
4. ลบ = -2^(N-1) = -32 → ช่วง signed = -32 .. 31
ระบบN = 6 บิตN = 8 บิต
Unsigned0 .. 630 .. 255
Signed-32 .. 31-128 .. 127

สูตรจำ (เอาไปใช้ได้ทุกข้อ)

Unsigned : 0 .. 2N-1
Signed : -2N-1 .. 2N-1-1

ตัวอย่าง (6 บิต)

signed มากสุด = 31, น้อยสุด = -32 — unsigned มากสุด = 63, น้อยสุด = 0

เลขฐาน 10 กี่หลัก → ต้องใช้กี่บิต?

หา N ที่ 2N-1 < ค่า ≤ 2N
เช่น ตัวเลข 10 หลัก (สูงสุด 9,999,999,999):
233 ≈ 8.6 พันล้าน < 1 หมื่นล้าน ≤ 234 ≈ 1.7 หมื่นล้าน
→ ต้องใช้ N = 34 บิต

Exam Tipข้อสอบถาม "มากที่สุด/น้อยที่สุดของ N บิต" — แทนค่า N ในสูตรเลย: 2N-1, -2N-1, 2N-1-1, 0

NUMBER SYSTEMS

Two's Complement — จำนวนลบในคอมพิวเตอร์

วิธีสร้างจำนวนลบ: กลับบิตทุกตัว (invert) แล้วบวก 1 — เช่น หา -6 ในระบบ 8 บิต

ขั้นตอน · หา -6 ในแบบ 8 บิต
1. เขียน 6: 00000110
2. กลับบิตทุกตัว: 11111001
3. บวก 1: 11111010 = 0xFA = -6

บิตเดียวกัน 0xFA — unsigned อ่านได้ 250, signed อ่านได้ -6

อ่านค่า signed แบบลัด

ถ้า MSB (บิตซ้ายสุด) = 1 → signed = ค่า unsigned - 2N เช่น 0xFA = 250 - 256 = -6

บิตเดียวกัน ความหมายต่างกัน

0xFA = 250 (unsigned 8 บิต) แต่ = -6 (signed 8 บิต) — ขึ้นอยู่กับว่าเราตีความแบบไหน

Exam Tipเจอเลข Hex ตัวแรก ≥ 8 (เช่น 0xfa) ในระบบ signed → ลองลบ 256 ก่อน: 250-256 = -6

NUMBER SYSTEMS · ARITHMETIC

การบวก-ลบ และการล้น (Overflow)

ข้อสอบแนวนี้ทำแค่ 3 ขั้นตอน — จำให้แม่น แล้วทุกข้อจะกลายเป็นเรื่องง่าย

วิธีคิด 3 ขั้นตอน · ใช้ได้กับทุกข้อ
1. คำนวณผลก่อน — ทำเลขปกติ: เช่น -125-10 = -135, 200+70 = 270

เมื่อไหร่เป็น err

เมื่อตัวเลขที่โจทย์ให้ (operand) เกินช่วงของระบบนั้น — เช็คก่อนเสมอ เช่น signed 8 บิตใช้ -130 หรือ unsigned ใช้ค่าลบ หรือเลขอย่าง -140 แทนใน 8 บิตไม่ได้ (ทั้ง signed/unsigned)

เมื่อไหร่ต้องวนรอบ

เมื่อ operand ทุกตัวอยู่ในช่วง แต่ ผลลัพธ์เกินช่วง → บวก/ลบด้วย 2N เช่น 270-256=14, 256-130=126
